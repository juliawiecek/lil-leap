Gap 1: Idempotency Race Condition (Application-Level)
  Status: DOCUMENTED (NOT FIXED)
  Issue: Two threads can both pass hasTerminalEventForOrder() check before either commits
  Window: Between read and write in same @Transactional method (microsecond race)
  Impact: High concurrency may create duplicate terminal events (ORDER_ACCEPTED, ORDER_FILLED, etc.)
  Mitigation Available: Add UNIQUE index on (related_order_id, event_type) for terminal events
  Deferral: NEXT-123+ (database-enforced idempotency)

Gap 2: SETTLEMENT_FAILED Not Implemented
  Status: DEFERRED WITH CLEAR DOCUMENTATION
  Issue: No post-rollback audit path exists for settlement failures
  Reason: Transaction rolls back → audit write is rolled back too
  Current: Throws UnsupportedOperationException if called
  Mitigation Available: Async failure queue or separate failure-log table
  Deferral: NEXT-123+ (post-rollback event recording)

  Status: NOT IN SCOPE
