# API Documentation

How to browse and try the lil-leap service APIs in Swagger UI. Each service publishes its
own docs, generated from its code, so they stay in step with what is deployed.

| Service | Swagger UI | Raw spec |
|---|---|---|
| `auth` | http://localhost:4200/auth/docs | http://localhost:4200/auth/docs-json, or [auth/openapi.json](../../auth/openapi.json) |
| `orders` | http://localhost:8082/api/v1/swagger-ui.html | http://localhost:8082/api/v1/v3/api-docs |
| `holdings`, `insights`, quote-service | Not published yet | – |

## Trying the APIs

1. Start the stack from the repo root: `docker compose up -d --build`
2. Open the auth and orders pages from the table above.
3. **Get a token:** on the **auth** page, run `POST /auth/login` with a trader's email and
   password. Copy `accessToken` and `user.id` from the response.
4. **Use it:** on the **orders** page, click **Authorize**, paste the token, then use
   **Try it out** on any endpoint. For `{id}`, use your `user.id`.

Tokens expire after 10 minutes of inactivity (BR-03). If calls start returning `401`, log in
again and re-authorize.

### On the shared EC2 server

Only port 8080 (Jenkins) is open from outside, so tunnel the ports from your machine and
then use the same `localhost` links:

```
ssh -L 4200:localhost:4200 -L 8082:localhost:8082 ec2-user@10.14.134.115
```

Keep that terminal open while you use the pages.

## auth

- Spec generated by [auth/src/docs/](../../auth/src/docs/) and committed as
  [auth/openapi.json](../../auth/openapi.json); it can also be opened in
  [editor.swagger.io](https://editor.swagger.io).
- Endpoints: `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`;
  `GET /rules/tier-eligibility`; `GET /health`.
- Auth has no port of its own; it is reached through the frontend's nginx on port 4200.

## orders

- Spec generated at runtime by springdoc from the controllers, so there is no committed
  file to go stale.
- Every orders URL is under the service's `/api/v1` context path.
- Endpoints:

  | Endpoint | Purpose | Roles |
  |---|---|---|
  | `POST /orders` | Submit a market BUY/SELL order (saved as `PENDING`, filled by the execution job) | `TRADER` |
  | `GET /clients/{id}/orders` | Order history with fills, newest first; optional `from`, `to` (ISO dates, inclusive) and `status` filters | `TRADER` |
  | `GET /clients/{id}/cash` | Cash balance | `TRADER`, `ANALYST` |
  | `GET /cash/balance/{clientId}` | Cash balance (alternative route) | `TRADER`, `ANALYST` |

- `{id}` / `{clientId}` must be your own user id. Anyone else's returns `404 CLIENT_NOT_FOUND`
  (BR-02).
- Errors come back as `{"error": "...", "message": "..."}`, for example `INVALID_REQUEST`,
  `INVALID_FILTER`, `ACCOUNT_NOT_FOUND` or `UNAUTHENTICATED`.

## Not documented yet

`holdings`, `insights` and the Python quote-service don't publish OpenAPI specs yet. When one
does, add a row to the table above and a section like the ones for auth and orders.
